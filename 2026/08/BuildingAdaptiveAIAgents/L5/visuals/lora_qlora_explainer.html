Rudder vs. cargo hold — why behavior steers but facts don't

The same low-rank bottleneck that makes LoRA cheap is why it steers behavior well but can't store facts. Compare its shape to the transformer's own MLP — the layer where facts actually live.

MLP — the cargo hold

stores facts
expand → gate → contract.
Projects up into a wide hidden layer (several × the model dim), through a nonlinearity (GELU / SwiGLU), then back down.

The nonlinearity makes each neuron a light switch — a real if-then. The wide gated layer acts like a key-value memory: keys detect a pattern, values write a fact back into the stream (the reading ROME / MEMIT exploit). This is where pretrained knowledge sits.

LoRA — the rudder

steers behavior
contract → expand, nothing in between.
Squeezes through a rank-r bottleneck and back up — pure linear, no switch.

So it's a dimmer knob, not a light switch: a bit more of this in proportion to that. Plenty for behavior — a low-rank direction (a tone, a refusal). A rudder can't carry cargo: thousands of specific facts are high-rank and don't fit.
This is exactly the split the two arms measure: persona behavior installs 0.00 → 1.00 and refusal suppresses 0.80 → 0.12 (steerable), while invented partner facts stay 0.00 (cargo — retrieve them via Module 3 instead). Caveat: "several × wider" is loose (classic 4×, SwiGLU ≈ 2.67×); key-value memory is a well-supported interpretation, not settled fact; clean single-concept neurons are a teaching fiction (real ones are polysemantic).

Rule of thumb: r=8 for efficient adaptation, r=32–64 when task divergence is large. α is usually set to 2× r (α/r = 2) so scaling doesn't dominate. Using r=64 costs ~8× more VRAM than r=8 for adapter layers — but the base is frozen so total VRAM still dominated by the frozen model.

Quantization: the Q in QLoRA

QLoRA loads the frozen base model in INT4 (4-bit NF4), cutting VRAM 4×. The LoRA adapters (B, A) remain in BF16/FP16. Toggle to see the precision bucket distribution.

FP16 — 32 buckets

FP16 — 16 bits per weight, ~32 effective precision buckets. Full resolution, high memory.


INT4 — 4 bits per weight (NF4 variant), ~16 buckets, optimized for normally-distributed weights. 4× memory reduction.


Accuracy loss from INT4 quantization of the frozen base is typically <1% on downstream tasks when LoRA adapters are trained on top.

Memory drops ~4× (140 GB → 35 GB for Llama-3.3-70B). LoRA factors B and A stay in FP16 — the tiny adapter gradient math runs in full precision while the frozen body saves memory.

Cumulative re-fits — the monotone suppression curve

Two cumulative arms, each trained fresh from the frozen 4-bit base with local Unsloth + QLoRA. The arms are sized so behavior-suppression climbs monotonically — behavior_rate is engages-on-unknown (lower is better), measured live on Gemma 3n E4B (A10).

⚠ No warm-start — each arm trains from scratch. Every cumulative re-fit starts from the frozen base model, not from the previous adapter, so each arm re-learns everything from the accumulated corpus. Teaching point: more corpus coverage needs proportionally more training — an earlier 4-shape v3 arm under-trained at fixed epochs and regressed suppression to ~0.50, so we removed it and reinforced v2 (more unknowns + more epochs) to keep the curve monotone.
The router (Module 4 script) picks base vs. the specialised adapter per request; the regression gate keys on the best arm (v2): behavior_rate_drop ≥ 0.5 AND kept_capability_rate ≥ 0.85.
